# R0 implementation plan

User direction: the full floating-archipelago reboot brief. Implement in this
session with the existing Three.js modules and native browser verification.

1. Record Phase 2 baseline (67 tests), preserve its modules/source records, create
   the dedicated branch and isolate the new world loader from legacy assembly.
2. Add a pure terrain/route plan, exact triangulated support lookup, tapered cliff
   geometry and palette. Add sky, clouds and initial licensed groves. Extend engine
   dependencies with backwards-compatible defaults, then inspect terrain captures.
3. If terrain gate is convincing enough for continued construction, create one
   terrain-responsive settlement: skyport gateway, split-canopy transit hall,
   market cluster and highland pavilion; import only a few approved variants.
4. Connect optional world-aware movement/camera, live research guide, map and
   editorial camera compositions. Make unbuilt-realm research buttons honest.
   Version stored positions and configure future travel without implementing it.
5. Test geometry/ground agreement, route traversal, collision, jumps, edge recovery,
   terrain camera clearance, source preservation, caches, load/unload and old suite.
6. Native browser loop: reveal, actual walking/running/jumping, research dialogue,
   MBR deep link, mode/history handoff, pause/quality, phone layout, failure recovery.
7. Capture ten real views and legacy comparison; record load/moving-frame resource
   measurements, manifests, remaining defects and flight recommendation. Stop.

Review focus: exact render/support agreement; highland slopes must be walkable;
camera rays must clear elevated terrain; legacy scenery must never load alongside
the island; MBR cannot teleport to an unbuilt realm; failed/cancelled loads must
dispose resources; only one active scene/renderer/animation loop.
